# 로컬 챗

내 서버의 로컬 LLM(Qwen, llama.cpp)에 연결하는 ChatGPT 스타일 채팅 사이트입니다.
회원가입/로그인, 계정별 대화 목록, 실시간 스트리밍 답변을 지원합니다.

- `apps/api` — Express 5 + TypeScript + PostgreSQL
- `apps/web` — React 19 + Vite + Tailwind v4
- 사이트 이름은 `apps/web/src/lib/brand.ts` 의 `APP_NAME` 에서 바꿉니다.
- 화면 상단에서 모델을 고를 수 있습니다. 목록은 `.env` 의 `LLM_MODELS` (예: `qwen3.5:9b=Qwen 3.5 9B,qwen3.5:4b=Qwen 3.5 4B`) 로 정합니다.
  모든 모델은 같은 `LLM_BASE_URL` 서버(llama.cpp 또는 Ollama)에서 제공돼야 합니다.
- 여러 명이 쓸 때는 모델을 **하나로 고정**하는 게 빠릅니다. 모델이 여러 개면 사람마다 다른 모델을 고를 때 GPU 에서 모델을 바꿔 끼우느라 기다리게 됩니다.

### 여러 명 동시 처리 (Windows, llama.cpp)

Ollama 는 Qwen 3.5 를 한 번에 한 명씩만 처리합니다. 동시에 처리하려면 llama.cpp 서버를 직접 띄웁니다.

```powershell
powershell -ExecutionPolicy Bypass -File scripts\start-llama.ps1
```

- 필요한 것: [llama.cpp 릴리스](https://github.com/ggml-org/llama.cpp/releases)의 `llama-*-bin-win-cuda-12.4-x64.zip` 과 `cudart-llama-bin-win-cuda-12.4-x64.zip` 을 같은 폴더에 풀기,
  모델은 `unsloth/Qwen3.5-9B-GGUF` 의 `Qwen3.5-9B-Q4_K_M.gguf`. **Ollama 의 모델 파일은 형식이 달라 쓸 수 없습니다.**
- 경로·동시 처리 수(기본 8)·한 사람당 대화 길이(기본 16384)는 스크립트 위쪽 값이나 환경 변수(`LLAMA_PARALLEL` 등)로 바꿉니다.
  `.env` 의 `LLM_BASE_URL=http://127.0.0.1:8081/v1`, `LLM_CONCURRENCY` = `LLAMA_PARALLEL`, `LLM_CONTEXT_TOKENS` = `LLAMA_CTX_PER_SLOT` 로 맞추세요.
- Ollama 와 같은 그래픽카드를 쓰므로 llama.cpp 를 쓸 때는 Ollama 를 꺼 두세요.
- Qwen 3.5 는 칸당 대화 기억 메모리가 약 0.56GB(16384토큰)라 8칸이 RTX 3070 × 2 (16GB) 에 들어갑니다 (사용 약 11.5GB).

### 공개 주소 (https://smcaichat.zlero.xyz)

- 이 PC 의 Cloudflare 터널 `smc-aichat` 이 `https://smcaichat.zlero.xyz` 를 `http://localhost:4100` 으로 이어 줍니다 (게임 사이트 터널 `smc-game` 과는 따로).
- 파일: `D:\chat-site-data\cloudflared\` (`cloudflared.exe`, `config.yml`, 터널 비밀 `smc-aichat.json`, 계정 인증서 `cert.pem` — 시스템·관리자만 읽을 수 있게 권한을 막아 둠), 기록 `tunnel.log`.
- `.env`: `COOKIE_SECURE=true`(로그인 쿠키는 https 로만), `TRUST_PROXY=1`(Cloudflare 를 거쳐 온 실제 접속 IP 로 로그인 시도 제한), `GOOGLE_REDIRECT_URI=https://smcaichat.zlero.xyz/api/auth/google/callback`.
- 쿠키가 https 전용이라 `http://192.168.x.x:4100` 같은 IP 주소로는 로그인이 유지되지 않습니다. 공개 주소나 이 PC 의 `http://localhost:4100` 을 쓰세요.

### PC 를 켜면 자동 실행 (Windows 작업 스케줄러)

| 작업 이름 | 하는 일 | 기록 |
|---|---|---|
| `chat-site llama.cpp` | `scripts\start-llama.ps1` (모델 서버, 포트 8081) | `D:\llama.cpp\llama-server.log` |
| `chat-site 사이트` | `scripts\start-site.ps1` (데이터베이스 + 배포 모드 사이트, http://localhost:4100) | `D:\chat-site-data\site.log` |
| `chat-site 터널` | `D:\chat-site-data\cloudflared\cloudflared.exe` (공개 주소 https://smcaichat.zlero.xyz) | `D:\chat-site-data\cloudflared\tunnel.log` |

- 둘 다 시스템 계정으로 로그인 없이 켜지고, 꺼지면 1분 뒤 다시 켜집니다.
- 데이터베이스는 `D:\chat-site-data\pgdata` 에 있습니다.
- 코드를 고친 뒤에는 `npm run build` 하고 다시 시작하세요:
  `Stop-ScheduledTask -TaskName 'chat-site 사이트'; Start-ScheduledTask -TaskName 'chat-site 사이트'`
  (모델 서버 설정을 바꿨으면 작업 이름만 `chat-site llama.cpp` 로 바꿔서 똑같이)
- 개발 서버(`npm run dev:api`)는 같은 4100 포트를 쓰므로, 개발할 때는 `Stop-ScheduledTask -TaskName 'chat-site 사이트'` 로 먼저 끄세요 (데이터베이스는 계속 켜져 있음).

## 빠른 시작 (개발)

```bash
npm install
cp .env.example .env      # JWT_SECRET(32자 이상), DATABASE_URL 등을 채우기
npm run dev:api           # http://localhost:4000 (시작 시 DB 마이그레이션 자동 실행)
npm run dev:web           # http://localhost:5173 (/api 는 4000 으로 프록시)
npm run invite -- 5       # 초대 코드 5개 발급 (npm run invite -- list 로 조회)
```

LLM 없이 화면만 보고 싶다면 `node scripts/fake-llm.mjs` (포트 8099) 를 띄우고
`LLM_BASE_URL=http://127.0.0.1:8099/v1` 로 지정하세요.
검증: `scripts/smoke.mjs` (가짜 모델로 API 기본 흐름 점검).

## 사용량 한도 (5시간)

- 사용자마다 5시간 동안 쓸 수 있는 토큰(질문 + 답변) 수가 정해져 있습니다. Claude 처럼 **첫 메시지를 보낸 때부터 5시간**이 지나면 0으로 돌아갑니다.
- 처음 기본값은 `.env` 의 `TOKEN_LIMIT_DEFAULT` (100,000). 관리자는 사이드바의 **관리자** 화면에서 기본값을 바꾸거나, 사용자마다 따로 정하거나(0 = 사용 막기), 사용량을 바로 초기화할 수 있습니다.
- 사용량이 80% 를 넘으면 입력창 위에 알림이 보이고, 다 쓰면 초기화 시각까지 메시지를 보낼 수 없습니다.

## 응답 스타일과 개인 지침

- **응답 스타일**: 기본 / 간결하게 / 자세히 설명 / 학습 도우미 / 격식 있게 를 기본으로 제공합니다 (`apps/api/src/styles.ts`). 사용자는 이걸 복사해 고치거나 직접 만든 스타일(최대 10개)을 입력창 왼쪽 아래나 설정에서 고를 수 있습니다.
- **개인 지침**: 스타일과 상관없이 모든 대화에 들어가는 나에 대한 정보·규칙입니다 (설정 화면).

## 내 컴퓨터 폴더 (Claude Code 처럼 파일 다루기)

- 입력창 왼쪽 아래 📁 → **내 컴퓨터 폴더 열기** 로 사용자 PC 의 폴더를 고르면 브라우저가 읽기·쓰기 권한을 묻습니다. 허용하면 그 대화에서 AI 가 그 폴더 안의 파일을 다룹니다.
  - 바로 실행: 폴더 보기(하위 폴더까지 한 번에도 가능), 파일 읽기, 내용 찾기, 이름으로 찾기(`*.py` 같은 와일드카드)
  - **허용해야 실행**: 파일 만들기·덮어쓰기, 고치기(여러 군데 한 번에 바꾸기 가능), 폴더 만들기, **이름 바꾸기·옮기기**, 복사, 지우기 (미리보기와 허용/거절 버튼이 뜹니다. 10분 안에 답하지 않으면 거절)
  - **권한 단계** (입력창의 "권한"): 읽기만 / 매번 물어보기(기본) / 고치기는 자동 / 모두 자동. 허용 카드의 "허용하고 앞으로 묻지 않기"로도 바꿀 수 있습니다. 이 브라우저에만 기억됩니다.
- 파일은 서버로 올라가지 않습니다. 서버는 모델의 도구 호출을 브라우저에 전달(`tool_exec`)하고, 브라우저가 그 폴더에서 실행한 결과(`POST /api/conversations/:id/tool-result`)를 모델에게 돌려줍니다. 단, AI 가 읽은 파일 내용은 답을 만들기 위해 모델 서버로 보내집니다.
- 폴더 밖으로는 브라우저가 접근을 막고, `..`·절대 경로도 거절합니다.
- **프로그램 실행** (선택): 브라우저는 프로그램을 실행할 수 없어서, 사용자 PC 에서 작은 도우미를 켜야 합니다. 사이트 서버는 명령을 실행하지 않습니다.
  1. 설정 → "프로그램 실행"에서 `chat-site-runner.mjs` 를 받습니다 (Node.js 18 이상 필요).
  2. AI 에게 맡길 폴더에서 `node chat-site-runner.mjs "폴더 경로"` 로 켜면 **연결 코드**가 나옵니다 (내 PC 의 `~/.chat-site-runner.json` 에 저장되어 계속 같은 코드).
  3. 설정에 코드를 붙여 넣고, 채팅에서 **같은 폴더**를 열면 AI 가 `run_command` 로 명령을 실행합니다. 허용은 입력창의 "권한" 단계를 따르며, "모두 자동"에서도 위험해 보이는 명령(인터넷 내려받기·삭제·폴더 밖 경로 등)은 묻습니다.
  - 도우미는 127.0.0.1 에서만 받고, 연결 코드와 허용한 사이트 주소(기본 `https://smcaichat.zlero.xyz`, 다르면 `--allow https://주소`)가 맞아야 합니다. 시작 위치는 작업 폴더 안으로 제한, 시간 제한(기본 120초, 최대 600초), 시간이 지나면 자식 프로그램까지 끕니다.
  - 한계: 명령 자체가 다른 곳을 건드리는 것까지는 막지 못합니다. 위험한 명령 목록은 마지막 안전망일 뿐이니 믿는 폴더에서만 켜세요. 메일을 읽은 답변에서는 명령 실행을 막습니다.
  - 시험: `node 시험파일` 형태로 보안·실행 시험을 했습니다 (연결 코드, 사이트 주소 검사, 한글 출력, 종료 코드, 폴더 밖 거절, 위험 명령 거절, 시간 초과, 긴 출력). 크롬에서 실제 연결은 사용자가 해 보셔야 합니다.
- 대화마다 고른 폴더는 그 브라우저(IndexedDB)에 기억됩니다. 페이지를 다시 열면 보낼 때 권한을 다시 물을 수 있습니다.
- **조건**: 크롬·엣지(컴퓨터)에서, 사이트를 **HTTPS** 주소(또는 localhost)로 열어야 합니다. 휴대폰·파이어폭스·사파리는 지원하지 않습니다.
- 도구 호출을 지원하는 모델이 필요합니다 (Qwen 3.5 9B / 3.6 확인). 모델이 "~하겠습니다"라고 말만 하고 멈추면 서버가 두 번까지 재촉합니다. 작은 모델은 엉뚱한 곳을 고칠 수 있으니 허용 전에 미리보기를 확인하세요.

## 예약 작업 (정해진 시각에 자동 실행)

- 사이드바의 **예약 작업**에서 이름, AI 에게 보낼 지시, 반복(매일 / 평일 / 요일 고르기 / 한 번만), 시각, 응답 스타일을 정합니다.
- 그 시각이 되면 서버가 지시를 AI 에게 보내고 결과를 **새 대화**로 저장합니다. 사이트를 닫아 둬도 실행되고, 사이드바에 시계 아이콘과 새 결과 점이 붙습니다. 사이트를 열어 두었고 알림을 허용했으면 브라우저 알림도 뜹니다.
- 서버는 30초마다 확인하므로 최대 30초쯤 늦게 시작할 수 있습니다. 서버가 꺼져 있어 놓친 실행은 다시 켜졌을 때 한 번만 실행합니다.
- 예약 실행도 그 사용자의 5시간 사용량에서 빠지고, 다 썼으면 건너뛰고 이유를 남깁니다. 예약 작업은 동시에 2개까지만 모델 칸을 써서 사람들의 대화를 막지 않습니다.
- 관리자는 사용자당 예약 작업 수를 정할 수 있습니다 (기본 10개, 0 = 막기).
- **웹 검색 사용**을 켜면 예약 작업도 검색·페이지 읽기를 해서 뉴스 요약 같은 일을 할 수 있습니다 (아래 웹 검색이 설정돼 있을 때).
- 한계: 내 컴퓨터 폴더 작업은 예약할 수 없습니다 (브라우저가 열려 있어야 해서).

## 웹 검색

- 입력창 아래 🌐 버튼으로 켜고 끕니다 (브라우저에 기억). 켜면 AI 가 필요할 때 **웹 검색**(`web_search`)과 **페이지 읽기**(`fetch_url`)를 직접 하고, 찾은 사이트들이 도구 기록 아래에 출처 링크로 남습니다.
- 검색은 서버가 합니다. `.env` 의 `WEB_SEARCH_PROVIDER` 로 고릅니다:
  - `searxng` (지금 설정): 직접 설치한 [SearXNG](https://github.com/searxng/searxng). 무료·키 없음. 이 PC 에서는 WSL Docker 컨테이너 `searxng` (`127.0.0.1:8888`, 설정 `/opt/searxng/settings.yml`, 자동 재시작)로 돌고 있습니다. 구글 등이 가끔 막아서 결과가 적을 수 있습니다.
  - `tavily` / `brave`: `WEB_SEARCH_API_KEY` 에 API 키를 넣습니다. (키가 없어 이 둘은 실제로 시험하지 못했습니다)
  - `none`: 끔 (🌐 버튼이 사라집니다).
- 페이지 읽기는 이 PC(localhost)·사설망(192.168.x.x 등)·클라우드 메타데이터 주소를 막습니다. 주소 이름이 실제로 어느 IP 로 가는지 연결할 때 확인하므로 리다이렉트나 DNS 로 우회할 수 없습니다. 글이 아닌 파일(PDF·이미지 등)은 읽지 않습니다.
- 페이지 하나에서 AI 에게 넘기는 본문은 `WEB_FETCH_MAX_CHARS`(기본 6,000자)까지입니다. 대화 길이(한 사람당 16,384토큰)를 아끼려는 값이라 너무 키우지 마세요.
- 작은 모델(9B)은 답에 출처 링크를 빠뜨리거나 날짜를 틀리게 옮기기도 합니다. 그래서 출처는 모델 답과 따로 화면에 보여 줍니다.

- **내보내기**: 대화 위쪽 ⋯ → "마크다운으로 저장"(.md) 또는 "PDF로 저장 / 인쇄"(인쇄 창에서 PDF 로 저장).

## 파일·이미지 첨부

- 입력창의 📎, 끌어다 놓기, 스크린샷 붙여 넣기(Ctrl+V)로 한 번에 5개까지 붙입니다. 파일 하나는 `MAX_UPLOAD_MB`(15MB)까지.
- **이미지**(PNG·JPG·WEBP·GIF): 브라우저가 긴 변 1280px 로 줄여 올리고, AI 가 직접 봅니다. 모델 서버에 그림 읽기 파일(`--mmproj`, `scripts/start-llama.ps1` 의 `LLAMA_MMPROJ`)이 있어야 합니다. 최근 질문 3개 안에 붙인 그림까지 다시 보여 줍니다.
- **문서**(PDF·워드 .docx·텍스트·코드): 서버가 글자를 뽑아 둡니다. 질문 하나에 `ATTACH_CONTEXT_CHARS`(8,000자)까지 넘기고, 길면 질문과 관련된 문단만 골라 넣습니다. 스캔한 PDF(그림), 한글(HWP), 엑셀·파워포인트는 아직 못 읽고 안내 문구를 보여 줍니다.
- 파일은 `UPLOAD_DIR`(이 PC 는 `D:\chat-site-data\uploads`)에 저장되고 주인만 열 수 있습니다. 올리기만 하고 보내지 않은 파일은 하루 뒤, 계정이 지워져 주인이 없어진 파일은 한 시간 안에 정리됩니다.

## 긴 대화 자동 요약

- 대화가 모델이 한 번에 읽을 수 있는 길이(한 사람당 16,384토큰 중 답변 자리를 뺀 만큼)를 넘으면, 앞부분을 요약해 대화에 저장하고 최근 메시지만 그대로 보냅니다. 또 넘치면 "이전 요약 + 그 뒤"를 다시 요약합니다.
- 요약하는 동안 "앞부분을 요약해 기억하는 중" 안내가 뜨고, 대화에는 "여기까지는 요약해서 기억하고 있어요" 줄이 그어집니다.
- 요약된 메시지를 고치면 요약은 버리고 필요할 때 다시 만듭니다.

## 프로젝트

- 사이드바의 **프로젝트**에서 만듭니다. 프로젝트마다 이름·설명, **프로젝트 지침**(그 안의 모든 대화에 들어감), **자료**(문서, 30개까지)를 둡니다.
- 프로젝트 화면의 "이 프로젝트에서 새 대화"로 시작하거나, 대화 위쪽 ⋯ → "프로젝트로 옮기기"로 기존 대화를 넣고 뺍니다.
- 자료는 질문 하나에 `PROJECT_CONTEXT_CHARS`(5,000자)까지 넣고, 많으면 질문과 관련된 문단만 고릅니다 (임베딩 없이 낱말 겹침으로 고르므로, 표현이 아주 다르면 놓칠 수 있습니다).
- 프로젝트를 지우면 자료는 같이 지워지고 대화는 남아 프로젝트에서만 빠집니다.

## 기억

- 답변이 끝나면 AI 가 그 대화에서 사용자에 대한 오래 가는 사실(이름, 전공, 관심사, "기억해"라고 한 것 등)을 뽑아 저장하고, 모든 대화의 시스템 프롬프트에 넣습니다. 새로 기억하면 답변 아래에 "💡 기억했어요"가 잠깐 보입니다.
- 비밀번호·카드·주민번호 같은 번호와 건강·정치·종교 같은 민감한 내용은 뽑지 않도록 지시하고, 뽑더라도 서버가 한 번 더 걸러 냅니다.
- 설정의 **기억**에서 켜고 끄기, 목록 보기·지우기, 모두 지우기, 직접 적어 넣기를 합니다. 한 사람당 100개까지.
- 기억을 뽑느라 답변마다 모델을 한 번 더 짧게 부릅니다 (답변이 끝난 뒤라 기다리지는 않음).

## 구글 로그인과 Gmail

- 로그인 화면의 **Google 로 계속하기**. 같은 이메일로 가입한 계정이 있으면 그 계정에 이어지고, 없으면 새로 만듭니다 (가입 방식이 초대면 초대받은 사람만). 이메일·비밀번호 로그인도 그대로 됩니다. 구글로만 가입한 사람은 설정에서 비밀번호를 정하면 이메일로도 들어올 수 있습니다.
- **Gmail 연결**: 설정 → 구글 계정 → Gmail 연결. **읽기 권한(gmail.readonly)만** 받습니다. 입력창의 ✉️ 를 켜면 AI 가 메일을 찾고(`gmail_search`) 읽어(`gmail_read`) 요약합니다. 예약 작업에서도 "Gmail 사용"을 켜면 "매일 아침 메일 요약" 같은 일을 할 수 있습니다.
- 보안: 구글 리프레시 토큰은 `JWT_SECRET` 에서 만든 키로 암호화해 저장합니다 (JWT_SECRET 을 바꾸면 Gmail 을 다시 연결해야 함). 메일 속 지시는 따르지 않게 하고, **한 답변에서 메일을 읽은 뒤에는 웹 검색·페이지 읽기를 막아** 메일 내용이 검색어나 주소에 실려 나가지 못하게 했습니다.

### 구글 콘솔 설정 (관리자가 한 번)

1. https://console.cloud.google.com 에서 프로젝트를 만듭니다.
2. **API 및 서비스 → 라이브러리**에서 **Gmail API** 를 사용 설정합니다 (로그인만 쓸 거면 생략).
3. **OAuth 동의 화면**: 사용자 유형 "외부", 앱 이름·지원 이메일 입력, 범위에 `openid`, `email`, `profile`, `.../auth/gmail.readonly` 추가, **테스트 사용자**에 사이트를 쓸 구글 계정들을 넣습니다 (최대 100명).
4. **사용자 인증 정보 → OAuth 클라이언트 ID 만들기 → 웹 애플리케이션**, "승인된 리디렉션 URI" 에 `.env` 의 `GOOGLE_REDIRECT_URI` 와 똑같은 주소를 넣습니다.
5. 나온 클라이언트 ID·보안 비밀을 `.env` 의 `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` 에 넣고 사이트를 다시 시작합니다.

### 알아 둘 점

- 리디렉션 주소는 **localhost** 또는 **https 도메인**만 됩니다. `http://192.168.x.x` 같은 IP 주소로 들어온 사람은 구글 로그인을 쓸 수 없으니, 여러 사람이 쓰려면 도메인과 HTTPS(예: Cloudflare 터널)를 붙이고 `GOOGLE_REDIRECT_URI` 를 그 주소로 바꾸세요.
- Gmail 읽기는 구글이 엄격하게 심사하는 권한이라, 심사를 받지 않은 앱은 "테스트" 상태로 **등록한 테스트 사용자(최대 100명)만** 쓸 수 있고 **7일마다 다시 연결**해야 할 수 있습니다. 연결이 만료되면 AI 가 "설정에서 다시 연결해 주세요"라고 알려 줍니다.

## 가입 방식

- 기본은 **초대 코드 가입** (`REGISTRATION_MODE=invite`). 열려면 `open`.
- `ADMIN_EMAIL` 로 가입한 계정은 초대 코드 없이 가입되고 관리자 권한을 받습니다.

## llama.cpp 서버

- **죽으면 자동으로 다시 켜집니다.** 시작 스크립트가 프로그램의 종료 코드를 그대로 돌려주므로(`exit $LASTEXITCODE`), 작업 스케줄러가 비정상 종료를 알아채고 1분 뒤 다시 켭니다(모델을 올리는 시간까지 합쳐 약 2~4분). 감시(`chat-site 감시`)가 5분마다 확인하는 것은 그 뒤의 안전망입니다. 사이트(`start-site.ps1`)도 같습니다.
- **프롬프트 캐시를 껐습니다**(`--cache-ram 0`, `LLAMA_CACHE_RAM` 으로 변경). 2026-10-28 에 이 빌드(b11606)가 "캐시가 꽉 차서 오래된 항목을 지우는" 순간 `GGML_ASSERT(t_start > 0) failed` 로 죽었기 때문입니다. 동시 8개 요청을 4번 연속 보내도 정상이었고 속도는 거의 같습니다. 근본 원인(llama.cpp 의 버그로 보임)은 확인하지 못했으니, 같은 증상이 또 나오면 새 빌드로 올려 보세요.

`deploy/llama-server.service` 참고. 핵심 옵션:
`--jinja --reasoning-format deepseek --parallel N` (N 은 `.env` 의 `LLM_CONCURRENCY` 와 맞추기).
GPU 8GB×2 환경에서는 `--n-cpu-moe` 값을 조절해 VRAM 에 맞추세요.
모델/양자화는 서버에서 직접 받아 경로를 지정합니다.

## 배포 (Docker + Nginx)

```bash
cp .env.example .env   # JWT_SECRET, DB_PASSWORD, ADMIN_EMAIL, LLM_* 채우기
docker compose -f deploy/docker-compose.yml --env-file .env up -d --build
docker compose -f deploy/docker-compose.yml exec app node apps/api/dist/scripts/invite.js 5
```

- HTTPS 는 앞단(Cloudflare, certbot 등)에서 붙이세요. 붙이기 전 HTTP 로 테스트하면 `COOKIE_SECURE=false` 가 필요합니다.
- Nginx 에서 SSE 를 위해 `proxy_buffering off` 가 꼭 필요합니다 (설정 포함됨).
- llama-server 는 외부에서 접근되지 않게 방화벽으로 막고 도커 호스트에서만 열어 두세요.

## 보안 / 비밀값

- 모든 비밀값(JWT_SECRET, DB_PASSWORD, API 키)은 `.env` 에만 둡니다. `.env` 는 git 에서 제외되고 `.env.example` 만 커밋됩니다.
- 액세스 토큰(15분)은 메모리에만, 리프레시 토큰은 httpOnly 쿠키에 두며 DB 에는 해시만 저장하고 사용할 때마다 교체합니다.
  새로고침·탭 여러 개로 갱신 요청이 겹쳐도 로그아웃되지 않게, 방금(30초 안) 교체된 토큰은 한 번 더 받아 줍니다. 로그아웃·비밀번호 변경으로 끊은 토큰은 바로 만료돼서 이 예외가 적용되지 않습니다.
- 모든 조회는 `user_id` 로 제한되어 다른 사람의 대화는 404 입니다.

## 백업과 복원

- 작업 스케줄러의 **chat-site 백업** 이 매일 새벽 4시에 `scripts/backup.ps1` 을 실행합니다 (SYSTEM 계정, 놓쳤으면 켜질 때 바로 실행).
  - 데이터베이스 전체를 `C:\chat-site-backup\chat-날짜-시각.ndjson.gz` 한 파일로 저장하고, 만든 뒤 다시 읽어 행 수를 확인합니다 (맞지 않으면 그 파일을 지우고 실패 처리).
  - 올린 파일(uploads)은 `C:\chat-site-backup\uploads` 로 복사합니다 (새로 생기거나 바뀐 것만).
  - 14일이 지난 백업은 지웁니다. 단, 백업이 계속 실패하는 경우에 대비해 최근 3개는 남깁니다.
  - 위치·기간은 `.env` 의 `BACKUP_DIR`, `BACKUP_KEEP_DAYS`. 데이터(D 드라이브)와 다른 디스크(C)가 기본입니다.
  - 지금 바로 백업: `powershell -ExecutionPolicy Bypass -File scripts\backup.ps1`
- **복원** (사이트를 먼저 끄세요: 작업 스케줄러에서 "chat-site 사이트" 중지):
  ```
  npm run restore -- C:\chat-site-backup\chat-20261015-040000.ndjson.gz
  ```
  데이터베이스에 이미 계정이 있으면 멈춥니다. 전부 지우고 덮어쓰려면 끝에 `--force`. 올린 파일은 `C:\chat-site-backup\uploads` 를 `UPLOAD_DIR` 로 복사하세요.
- 시험: 백업을 빈 데이터베이스에 되돌려 15개 표의 행 내용을 해시로 비교했고 모두 같았습니다.
- 한계: 같은 PC 안의 다른 디스크라서 PC 자체가 사라지면(화재·도난·랜섬웨어) 같이 사라집니다. 가끔 `C:\chat-site-backup` 을 외장 디스크나 클라우드로 복사해 두세요.

## 계정 관리 (비밀번호 찾기·삭제)와 약관

- **비밀번호를 잊었을 때**: 이메일 발송이 없어서 관리자가 일회용 링크를 만들어 전해 줍니다. 관리자 화면 → 사용자 → **비밀번호 재설정 링크** → 나온 주소를 그 사람에게만 전달. 1시간 안에 한 번만 쓸 수 있고, 새로 만들면 이전 링크는 무효입니다. 바꾸면 그 사람의 모든 기기 로그인이 풀립니다. (DB 에는 토큰 원문이 아니라 해시만 저장)
- **계정 삭제**: 설정 → 계정 삭제. 이메일을 똑같이 입력해야 하고, 비밀번호가 있는 계정은 비밀번호도 맞아야 합니다. 대화·메시지·첨부 파일(디스크 포함)·기억·예약·프로젝트·공유 링크와 Gmail 연결(구글에도 권한 반납)이 모두 지워집니다. 사용 기록은 누구의 것인지만 지우고 통계로 남습니다. 마지막 관리자는 지울 수 없습니다. 백업에 남은 사본은 `BACKUP_KEEP_DAYS`(14일) 안에 사라집니다.
- **개인정보 처리방침 `/privacy`, 이용약관 `/terms`**: 로그인 화면 아래 링크로 연결됩니다. 문의 이메일은 `.env` 의 `CONTACT_EMAIL` (비우면 `ADMIN_EMAIL`)이 그대로 공개되니, 개인 메일을 숨기려면 따로 정하세요. 구글 OAuth 동의 화면의 "개인정보처리방침 링크"에 `https://smcaichat.zlero.xyz/privacy` 를 넣으세요.

## 디스코드 봇 (사용자가 설정에서 직접 연결)

각 사용자가 **설정 → 디스코드 봇**에서 자기 봇을 연결하면, 디스코드에서도 이 사이트의 모델과 대화할 수 있습니다. 봇 하나가 사용자 한 명에 연결되고, 이 서버(API)가 그 봇들을 대신 켜 둡니다.

**사용자가 하는 일** (설정 화면에 같은 안내가 있습니다)
1. [디스코드 개발자 포털](https://discord.com/developers/applications) → **New Application**.
2. **Bot** 메뉴 → **Reset Token** 으로 토큰을 만들어 복사. 같은 화면에서 **Public Bot 은 끄고**, 지정한 채널에서 멘션 없이 채팅하려면 **Message Content Intent 를 켭니다** (안 쓰면 꺼 둬도 됨).
3. 토큰을 설정의 "봇 토큰" 칸에 붙여 넣고 **연결**. 사이트가 디스코드에 물어서 진짜 봇 토큰인지 확인합니다.
4. 나온 **서버에 봇 초대하기** 링크로 자기 서버에 초대 (서버 관리 권한 필요).
5. (선택) 설정에 **답할 채널 ID** 를 넣으면 그 채널에서는 **그냥 채팅만 쳐도** 답합니다.

**디스코드에서 쓰는 법**
- **지정한 채널**: `/ask` 나 @멘션 없이 채팅만 쳐도 답합니다. 사람끼리 하는 말은 앞에 `//` 를 붙이면 무시합니다. (채널 ID 를 넣고 "그냥 채팅만 쳐도 답하기"를 켠 경우. 스레드는 부모 채널 설정을 따름)
- 다른 곳: `/ask 질문` (옵션 **파일**: 같이 볼 첨부, **깊게**: 먼저 생각하고 답함), 봇 @멘션, DM. `/reset` 은 이 채널 대화 기억 지우기, `/help` 는 사용법.
- **파일·이미지 읽기**: 메시지에 이미지(PNG·JPG·WEBP·GIF), PDF, 워드(.docx), 텍스트·코드 파일을 붙이면 봇이 보고 답합니다 (한 번에 4개, 한 파일 `MAX_UPLOAD_MB` 15MB, 이미지는 3장). 파일만 올려도 됩니다. 긴 문서는 질문과 관련된 부분만 골라 모델에 넣고, 읽지 못한 파일(HWP·엑셀·깨진 파일·너무 큰 파일 등)은 이유를 답 끝에 알립니다. **첨부는 읽을 때만 쓰고 서버에 저장하지 않으며**, 대화 기억에는 파일 이름만 남습니다. 첨부 주소는 `cdn.discordapp.com`·`media.discordapp.net` 만 내려받습니다.
- **봇이 파일 올리기**: "이 코드를 main.py 로 줘", "표를 CSV 파일로 만들어 줘"처럼 부탁하면 모델이 `send_file` 도구로 **글로 된 파일**(코드·마크다운·CSV·JSON 등)을 만들어 채널에 올립니다. 한 답변에 4개, 1MB까지. 이미지·PDF·엑셀·압축 파일은 만들 수 없고, `.exe`·`.bat`·`.dll` 같은 실행 파일 종류는 `.txt` 로 바꿔 올립니다. 파일 이름의 경로 문자는 모두 지웁니다.

**동작과 제한**
- 봇이 답하는 데 쓴 양은 **봇 주인의 5시간 사용량**에서 빠집니다 (서버의 다른 사람이 불러도 주인 몫). 주인 한도를 다 쓰면 봇이 그렇게 알리고 멈춥니다. 지정한 채널에서 모든 글에 답하는 만큼 사용량이 빨리 쓰이니, 믿을 사람만 쓰게 하려면 설정에서 **봇을 쓸 수 있는 디스코드 ID** 를 넣으세요 (디스코드 설정 → 고급 → 개발자 모드 → 우클릭 → ID 복사). DM 허용 여부와 켜기/끄기도 설정에 있습니다.
- 봇을 부르는 디스코드 사용자 한 명당 시간당 `DISCORD_MESSAGES_PER_HOUR`(20), 하루 `DISCORD_MESSAGES_PER_DAY`(100). 한 사람은 한 번에 질문 하나. 봇마다 동시에 2개까지 처리하고, 모델 자리는 사이트와 같은 줄(8칸)을 함께 씁니다. 줄이 꽉 차면 "사용자가 많아요"라고 답합니다.
- 모델 입력 길이(`LLM_CONTEXT_TOKENS` 16384 − 답변 `LLM_MAX_OUTPUT_TOKENS` 6144)에 맞춰 첨부 문서 → 지난 대화 순으로 줄여 넣습니다.
- 인터넷·메일·사용자 컴퓨터 파일은 볼 수 없는 대화 + 위 파일 기능만 합니다. 대화 기억은 메모리에만(채널+사용자별 최근 10개 메시지, 30분) 두고 서버를 다시 켜면 사라지며, 질문·답변·파일 내용은 로그에 남기지 않습니다. 답변 속 `@everyone`·멘션은 무력화해 알림이 가지 않게 합니다. 첨부 문서 안의 "지시를 무시하라" 같은 말은 내용일 뿐 따르지 않도록 지시해 둡니다.
- **토큰 보관**: AES-256-GCM 으로 암호화해 저장 (키는 `JWT_SECRET` 에서 이 용도 전용으로 만듦). 응답·화면에 다시 내려주지 않고, 연결을 끊거나 계정을 삭제하면 지워집니다. 같은 봇을 두 계정이 동시에 쓸 수 없습니다.
- 서버를 다시 켜면 연결된 봇이 자동으로 켜지고, 30초마다 설정 변경(토큰 교체·끄기·허용 목록)을 반영합니다. 채널 대화를 켜거나 끄면 메시지 내용 권한이 달라져서 봇이 한 번 다시 로그인합니다. **Message Content Intent 가 꺼져 있으면** 설정에 안내와 함께 "문제가 있어요"가 뜨고, 포털에서 켠 뒤 **다시 연결**을 누르면 됩니다. 토큰이 잘못됐거나 취소돼도 같은 표시가 뜨며 토큰을 바꿀 때까지 다시 시도하지 않습니다.
- 관리자 비상 스위치: `.env` 의 `DISCORD_BOTS_ENABLED=false` 로 모든 봇을 끌 수 있습니다.
- 시험(`npm test`, 가짜 디스코드·가짜 파일 서버): 토큰 확인·암호화 저장·중복 거절·채널 대화 설정, 첨부 내려받기(주소 제한·크기 제한·리다이렉트 거절)와 읽기(텍스트·이미지·깨진 파일·미지원 형식), 길이 맞추기, 파일 이름 안전 처리와 `send_file`, 메시지 나누기·제한·줄 세우기·멘션 무력화. 진짜 모델로는 이미지(빨간 그림 → "빨강")·문서(회의록 날짜)·`send_file` 호출(sum10.py 생성)을 확인했습니다. **실제 디스코드에 로그인해서 채널 글을 읽고 파일을 올리는 부분은 진짜 봇 토큰으로 직접 확인해야 합니다.**

## 시험과 감시

- **자동 시험** `npm test` (약 25초, 58개): 임시 데이터베이스(`chat_test_xxxx`)를 만들어 가입·초대 코드·로그인·갱신, 디스코드 봇 연결 설정(토큰 암호화·중복 거절), 비밀번호 재설정(한 번만·만료·이전 로그인 해제), 계정 삭제(데이터가 함께 사라짐·마지막 관리자 보호), 백업 스크립트를 확인하고 끝나면 지웁니다. 예약 시각 계산, SSRF 차단, 관련 부분 고르기, 폴더 도구 정의, 권한 단계 판정도 시험합니다. 실제 데이터에는 손대지 않습니다.
- **감시** 작업 스케줄러 `chat-site 감시` 가 5분마다 `scripts/watchdog.ps1` 을 실행합니다.
  - 사이트(`/api/health`), 모델 서버(8081 `/health`), 공개 주소를 확인하고, **2번 연속 실패하면** 해당 작업(사이트/llama.cpp/터널)을 다시 시작합니다. 디스크 여유 10GB 미만, 백업이 36시간 넘게 없을 때도 알려 줍니다.
  - 같은 문제로 알림을 반복하지 않고, 다시 정상이 되면 한 번 알립니다. 기록: `D:\chat-site-data\watchdog.log` (1MB 넘으면 교체).
  - 알림 받기: `.env` 에 `ALERT_WEBHOOK_URL=` 디스코드(서버 설정 → 연동 → 웹후크) 또는 슬랙 웹훅 주소를 넣으세요. 비우면 로그에만 남깁니다.
